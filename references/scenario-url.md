# 网页/URL 场景模板

## 适用
网页文章、博客、技术教程、论坛帖子

## 提取策略

1. 使用 `web_fetch` 抓取网页内容（默认 extractMode=markdown，自动去噪）
2. 从正文中提取：标题 → 章节标题 → 段落要点
3. 忽略导航栏、侧边栏、评论区等噪音（readability 模式会自动处理大部分）
4. 根据文章长度决定层级深度：短文 2-3 层，长文 3-4 层
5. 每个节点控制在 30 字以内，是「要点提炼」不是「原文复制」

## 结构化要领

- 第一层（主分支）：按文章的自然章节划分，通常 4-7 个主分支
- 第二层（子节点）：每个章节的核心概念或论点
- 第三层（叶子）：具体细节、示例、代码片段名称
- 禁止跨分支关联线 `[1]`/`[^1]` — 会导致 XMind 飞线混乱
- 使用 `[B]` 边界框对同类主题分组，`[S]` 总结节点汇总关键结论
- 禁止使用 `[B]:` 和 `[S]:` 标题语法 — xmindmark 0.3.2 有解析 bug

## XMindMark 模板

```
{网页标题}

- {章节1} [B1]
    * 核心概念1
        - 细节1
        - 细节2
    * 核心概念2
        - 细节1

- {章节2} [B2]
    * 要点1
        - 具体说明
    * 要点2
        - 具体说明

- {章节3} [B3]
    * 子主题1
    * 子主题2
    * 子主题3

- {章节N}
    * ...

- 关键结论 [S1]
    * 最重要的观点1
    * 最重要的观点2
    * 实用建议
```

## 实战案例：看雪论坛技术文章

输入：`https://bbs.kanxue.com/thread-286929.htm`（Android加固技术文章）

输出结构：
- 概述 — 四代加固技术、目标读者
- 前置知识 — Java反射、ClassLoader、DEX结构
- Java反射详解 — 核心类、获取方式、优缺点
- ClassLoader机制 — Java体系、双亲委托、Android体系
- 四代加固技术 — 落地→不落地→抽取→Dex2C
- 项目代码结构 — AndroidShell/ReadDex/ShellScripts
- 关键结论 — 5条核心要点

关键经验：长文技术文章每个主分支 3-7 个子节点最优；用 [B] 分组让逻辑关系可视化；不用关联线避免飞线。
